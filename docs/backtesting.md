# 策略回测

从侧栏进入「策略回测」，或打开 `http://127.0.0.1:8765/#backtest`。回测读取独立的历史缓存，不使用交易工作台的示例行情，不修改真实账户、持仓、交易模式或策略运行。

## 使用

1. 启动本项目服务及 NinjaTrader 8090 数据桥。在历史数据区选择时间、周期和拉取品种；默认 MNQ、MES、MGC、MCL。月份为空时使用桥返回且点值、最小跳动均校验通过的唯一当前月份；也可填写 `MNQ 12-26` 这样的完整原生名称。裸根代码不作为月份合约使用。
2. 点击「拉取K线并保存到本地」。完成后可断开数据桥，使用缓存离线回测。各品种独立报告读取失败，不补造缺失或休市 K 线；重复拉取按合约、周期和时间覆盖同根数据。
3. 选择「随机下单」及执行参数、账户方案、费用与滑点，点击开始回测。模拟账户数支持 1–1,000,000（包含 10,000）；勾选「∞ 不限账户总数」则不设固定总数。可复制已保存的自动策略参数；回测改参不改变运行中的策略。任务、最近一次已提交参数及每次结果均持久化，重启后可重载。
4. 结果区仅保留「多轮统计」：各轮平均表现、汇总交易统计、阶段平均单数及持仓时间、三条资金曲线。测试一轮也使用同一统计界面；下拉框可切换已保存测试。逐轮与逐笔记录仍在本地保存，页面不展示明细。
5. MNQ 长区间回测可在「本地行情数据」选择「MNQ 连续 · 后复权」，跨越季度换月使用；月份合约适合只测试其有效日期内的原始成交价格。当前连续数据为一分钟周期。

## 多轮随机种子与并行耗时

在「05 · 多轮随机种子与耗时」填写测试轮数及并行任务数，轮数默认为 1，允许 1–2³² 个整数。每次开始时，第一轮及所有后续轮次都由操作系统随机源独立选择 **128 位种子**，不再手填起始种子或逐轮加 1。种子以 `0x` 开头的32位十六进制字符串存储及传输，避免 JavaScript 大整数精度丢失。每轮独立重置账户和资金，并重新使用同一段历史；∞ 表示每轮内部持续补充账户，与测试轮数分开。

种子由 Python `secrets.token_hex(16)` 生成，父进程在派发前写入 `bt_round_seeds`，以批次内唯一约束检查重复并重抽；只按任务派发进度生成，不提前把全部轮次放入内存。完成结果及多轮记录也保存实际种子，已派发但中断的种子分配记录仍保留。

策略内的账户抽样、方向和等待间隔改用 **PCG64DXSM**（NumPy BitGenerator，经 SeedSequence 初始化）。为单标量调度缓存原始64位随机字；整数采用拒绝采样去除取模偏差，账户采用稀疏 Fisher–Yates 无放回抽样，内存只随批量大小增长。每轮单独创建生成器，不共享进程状态，也不使用进程号或时间戳拼接种子。同一轮的含手续费 / 不含手续费对照使用相同种子各自初始化，保证可重复比较。[NumPy 并行随机数说明](https://numpy.org/doc/stable/reference/random/parallel.html)、[PCG64DXSM 定义和固定种子整数流保证](https://numpy.org/doc/stable/reference/random/bit_generators/pcg64dxsm.html)。

结果记录 `rng_algorithm: pcg64dxsm_v1`、采样器版本、NumPy版本和实际种子；固定参数、数据、算法及种子可复现该轮。新提交会重新抽种子，查看历史记录不会重新随机化。历史配置未注明算法时仍按原 MT19937 复核，原始种子及结果不改写。安装回测依赖：`python -m pip install -r requirements.txt`。

并行任务采用独立 CPU 进程，利用多个核心计算不同轮次，避开普通 Python 线程的 CPU 限制。默认最多 4 个，允许范围为本机可用逻辑 CPU 数与 32 的较小值；实际并行数不超过轮数。每个进程只读自己的历史快照并独立写入临时明细，完成后由主服务汇总到 SQLite，不访问任何下单接口。只保持有限个待处理任务，填写很大的轮数不会提前创建所有账户或任务。

点击「测量单轮耗时」会随机生成一个种子，用当前数据、参数计算一轮并丢弃结果，不添加回测记录、不修改已保存表单。测量计算耗时后增加 20% 保存开销作为初步单轮预估；存在相同配置的历史执行耗时则优先复用。种子、轮数及并行数变化可复用测时；行情、算法版本及策略参数变化后需重新测量。界面显示单轮和全部轮次的预计总耗时，按并行批数、竞争开销和启动开销估算，并展示粗略范围；CPU 负载、写盘及不同种子的持仓路径会造成差异，该范围不代表统计置信区间。

运行时显示完成轮数、已用时间、预计剩余时间。可点击「停止本次测试」取消未完成计算，已完成轮次和完整明细保留。服务重启会标记批次中断，不自动续跑；可以查看已完成结果，或开始一个重新随机抽种子的新批次。

汇总显示各轮指标的算术平均、最小值、最大值及总体标准差，每轮等权，只纳入已完成轮次。交易统计合并全部已完成轮次的账户、交易数及持仓秒数后计算，避免将不同交易数的轮次简单平均。全部结果在独立批次表中持久化。

资金曲线为累计已到账分润减累计购号成本。固定账户池从区间起点计入全部计划账户成本，∞ 在实际补号时计入。交易结束后停止开仓、平仓及补号，只将已经申请的分润按原定到账时间全部结算；曲线延伸到最后一笔到账，尾段不需要更多 K 线，也不产生资金费、手续费或交易盈亏。模拟时间直接推进，不实际等待到账延迟。

最好及最差按结算后的最终净额选出完整的一轮曲线。各轮最后到账时间可能不同，汇总采用所有时间点的并集，较早结算完成的轮次保持最终金额；平均线按对应时点的阶梯余额计算，不用直线插值提前计入未到账资金。两种费用口径分别计算并选取最好、最差轮次。

「含交易手续费 / 不含交易手续费」仅切换资金曲线，上方统计始终沿用配置的费用。不含手续费会对同一组种子完整重算，交易手续费置零，保留滑点、资金费、购号成本及所有账户规则，并独立完成期末分润结算；通过时间、失败与分润路径因此可以变化。单轮测时与总时间估算包括这两次计算。旧结果可从完整保存的实际分润明细重新汇总结算，原始结果及成交记录不改写。旧免手续费对照未保存未到账申请，无法还原其尾段，需要重新回测，不将实际费用口径的分润套用过去。历史分润明细不完整时会标注仍为截止时口径。

## 账户方案与策略

按用户选择，默认沿用当前账户方案：通过页面固定回撤金额识别名义 5K 两阶段方案，而非把首次观察到的已亏损余额当成本金。默认本金 5,000、阶段目标 500 / 250、静态最大回撤 300、日亏损 3%、分润 80%、购号成本 15。所有这些值可编辑；未知或自定义方案需核对后设置。[Vest 账户方案](https://docs.vestmarkets.com/vest-capital/account-tiers)

当前自动策略登记为 `random_entry`（随机下单，版本 1），实盘调度与回测共用 `server/strategies.py` 中的策略 ID、账户抽样及方向选择。新增策略应登记名称、版本、支持市场并实现其选择逻辑；前后端通过策略目录显示选项，未知 ID 拒绝运行。当前增加四个品种的历史回测，并未扩展浏览器的 NQ-PERP 交易范围。

每批随机选择完整的一批虚拟账户，按随机订单间隔依次开仓，整批平仓后再等待随机批间隔。固定账户池耗尽后不补新号；∞ 模式优先使用已有的合格账户，不足一批时只补足所需的新账户，继续运行到所选区间最后一根可用 K 线结束（不补造行情）。每个新号从所选起始阶段及初始资金开始，并计入购号成本。秒级间隔落到下一根可用 K 线的开盘；默认每个账户每阶段每交易日最多一单、下一交易日可再次参与。关闭「每日重复」后，同一账户每阶段只参与本轮一次，复现单次运行的使用限制。阶段通过后重置该阶段资金并允许新阶段后续参与。

仓位按本金、所选比例、杠杆及入场费推算购买力；默认下取整为微型合约等值数量。不足一份时跳过并统计，不虚构成交。另有允许小数的等值数量模式。此计算是回测假设；真实下单仍以页面百分比按钮给出的数量为准。市场杠杆默认采用官方上限，可按页面实际杠杆降低。[Vest 杠杆与微型合约换算](https://docs.vestmarkets.com/trading/cross-margin-and-leverage)

条件止损沿用自动策略：开仓前以当时资金减静态回撤底线计算剩余回撤；启用且严格小于阈值时不设单笔止损，否则使用填写的止损金额。账户风控线仍生效。

## 规则、费用和成交假设

- 静态回撤底线为每阶段初始资金减最大回撤。日亏损基准按美东每天 **20:00** 的现金余额重置，包含持仓保留资金而不计浮盈；用净值判断是否低于底线，恰好等于不算违规。分润申请扣减日亏损底线。策略开仓额度的日切单独沿用 **17:00**，两者均处理纽约夏令时且可配置。[Vest 亏损限制](https://docs.vestmarkets.com/vest-capital/loss-limits.md)
- 指数及商品 Taker 费默认 **单边 0.25 bps，即 0.0025%**，开平仓均按实际模拟成交名义金额从该考核 / Live 账户的余额扣除。评估达标按扣除离场手续费后的余额确认；Live 按扣费后的净利润分润。总出金与现金曲线不再减一次交易手续费，曲线中直接扣除的成本只有购号成本；期末分润到账也不再扣交易手续费。[Vest 市场费用](https://docs.vestmarkets.com/trading/markets.md)
- 滑点单位通过 **tick / USD** 按钮切换，两种单位分别保留填写值。tick 默认每边 1 个最小跳动，体现在不利成交价格中，金额随合约数量变化。USD 按**整笔订单每边总额**计算，例如填 4 USD，开仓扣 4、平仓再扣 4，不乘合约数量；作为独立现金成本扣减，价格仍按最小跳动对齐。开仓预算预留该金额，净盈亏、风控、阶段目标、分润及免手续费曲线均包含它；`total_fixed_slippage_usd` 单列此现金成本，不混入交易手续费，也不会再重复改变成交价。
- 插件 0.3.18 可在已配对的 NQ 订单页面只读观察准确标为 Fee / Slippage 的可见行，保存百分比、时间与当时名义金额；界面按报价时名义金额换算为整笔订单 USD 滑点，缺少名义金额时只允许套用手续费。页面显示的滑点容忍度、零数量、隐藏或歧义报价不作为滑点。明确套用后保存到本次参数。
- 旧 bps 结果保留原参数和计算口径，以兼容历史复核。旧表单在编辑视图中按所选区间首根价格、初始资金/仓位/杠杆估算初始买入订单名义金额，再换算为固定 USD，并显示换算说明。两种模型在其他日期和数量下并非等价，不能直接将原来的数字改标 USD。缺少参考行情时 USD 输入留空，需填写金额或选择 tick。仅查看表单不会改写原参数；下一次提交测试时保存新单位。
- 订单面板的滑点是当前数量和流动性的预估，不能代表历史所有订单。CME K 线没有 Vest 历史盘口、永续基差、资金费或真实成交序列，因此回测始终展示成本来源和假设。历史资金费无法还原，采用固定每小时参数，默认 0，跨缺口的持仓也计入该假设。
- 成交价按不利方向取整到最小跳动。已知开盘先于当根高低点；跳空越过止损按更差开盘处理。开盘未触发退出、当根同时触及盈利目标及止损或风控线时，先处理不利退出。K 线内准确先后和持仓秒数无法还原，普通触发记于该根结束时间。
- 两个评估阶段通过后进入 live。live 的「出金目标」是用于平仓的可编辑模拟条件，默认 250，**不是 Vest 强制的 live 盈利目标**；填 0 则不使用目标退出，仍可在其他退出时申请利润。
- 仅空仓后申请可领取利润，从账户扣除申请的全部利润，再按分润比例计入待到账；默认延迟 24 小时。截止后停止交易，将全部已申请分润按原到账时间结清，再统计最终总出金、出金率和单号平均出金。截止时待到账金额以 `pending_payout_at_cutoff` 保留，`settled_after_cutoff` 单列尾段到账且已经计入总出金；最终 `pending_payout` 为 0。出金表示分润计入主账户，不等同钱包链上提现。[Vest 分润规则](https://docs.vestmarkets.com/vest-capital/claiming-profit)
- 期末未平仓按最后一根收盘价、不利滑点及离场费结算，成交原因单独标记。期末平仓可触发阶段通过或分润申请，延迟仍按原规则计算；没有后续行情时不会假设继续交易或提前到账。

## 统计口径

| 指标 | 计算 |
| --- | --- |
| 胜率 | 扣除双边费用及资金费后盈利的已平仓交易 / 全部已平仓交易 |
| 总净盈亏 | 全部虚拟账户所有阶段已平仓净盈亏之和，包含评估阶段的虚拟利润 |
| 考试通过率 | 已到达 live 的账户 / 从评估开始的统计账户；固定池包含未参与账户，∞ 采用实际生成数；从 live 开始则不适用 |
| 出金率 | 结清已申请分润后，至少一笔正额分润到账的账户 / 统计账户数（固定池全部计划账户；∞ 实际生成账户），同一账户多笔到账只计一次 |
| 总出金 | 交易截止前到账及截止后结清的已申请分润总额 |
| 截止后到账分润 | 交易结束后按原定到账时间结清的分润，已经包含在总出金中 |
| 单号平均出金 | 总出金 / 同上统计账户数，包括失败、未出金及固定池未参与账户 |
| 各阶段平均单数 | 该阶段开仓单数 / 实际进入该阶段的账户数 |
| 各阶段平均持仓时间 | 该阶段已平仓交易持仓秒数之和 / 该阶段已平仓笔数 |
| 每号平均单数 | 全部已完成轮次开仓单数 / 统计账户总数，固定池包含未参与账户，∞ 按实际生成数 |
| 平均持仓时间 | 全部已完成轮次已平仓持仓秒数之和 / 已平仓笔数 |
| 出金减购号成本 | 已到账分润减全部虚拟账户购号成本，与总净盈亏分开 |

随机种子、模型版本、策略版本、全部配置、逐笔交易及数据指纹随结果保存；相同模型版本、数据和参数可重现。v2 改用按需抽样；v3 增加现金曲线、持仓统计及双费用模拟；v4 增加每笔每边固定 USD 滑点；v5 增加期末分润结算；v6 增加独立随机128位种子和 PCG64DXSM 算法，历史原始结果保留。默认 50 个虚拟账户，固定池最多 1,000,000 个，也支持 ∞ 持续补号。原来 1,200 万账户 K 线及 10 万笔成交限制已移除；按需创建账户、只逐根处理当前持仓，完整明细分批写入 SQLite。主结果各保留最多 500 条预览，统计覆盖全部记录；页面仅请求汇总，不加载账户或成交列表。随机策略单次结果仅代表该数据窗口与随机种子，不能据此声称未来通过率或收益。
