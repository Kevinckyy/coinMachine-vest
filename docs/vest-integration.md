# Vest 网页接入核实记录

核实日期：2026-11-04（Asia/Shanghai）。仅访问公开文档、交易页与其公开 JavaScript 构建文件；没有登录、访问用户凭证、调用私有交易接口或下单。以下控件来自静态代码检查，仍须在用户实际登录页面校准。

## 接入边界

- 官方 [Vest Capital 说明](https://docs.vestmarkets.com/vest-capital/overview.md) 的 Requirements & limits 明确：考核及 Live Funded 账户当前均不提供 API 交易；个人 Live / Evaluation 账户数量也有上限。旧 Vest Exchange API 不可直接当成此 prop 产品的有效接口。
- 当前选择本地浏览器桥接：用户自行登录；读取可见页面；通过已校准的界面控件操作。浏览器扩展不读取钱包私钥、认证存储或网络令牌。
- 官方 [Prop Terms](https://next.vestmarkets.com/prop-terms-of-service) 的当前公开构建版本标注 2026-10-28 更新。第 2 节限制按用户合计，不能以多个身份绕过；第 5 节约束操纵、对敲、利用延迟及滥用多账户等行为。本次未找到概括性允许或禁止一般浏览器自动下单的明确表述；这不构成对自动化已获平台许可的确认。随机延迟用于错峰排队，不应描述为隐藏自动化或规避规则。
- 未验证实际登录状态、真实账户、WebSocket 连通性或交易执行结果。界面变更、休市、额外提示、掉线都可能中止执行。

## 交易数量及金额含义

[官方数量说明](https://docs.vestmarkets.com/trading/cross-margin-and-leverage)：NQ/ES 的 **1 Vest 单位，每 1 点变动对应 1 USDC**；1 MNQ 等价 2 Vest NQ 单位，1 CME NQ 等价 20 Vest 单位。不得把“1 Vest 单位”按 CME NQ 合约乘数计算。

网页数量的 USDC 模式表示名义价值，不是保证金；当前按用户要求自动选择 Micro 微型；NQ 的 Micro 整数数量转换为 2 倍 Vest 单位再与持仓数量核对。服务账本和网页持仓行仍用 Vest 单位，禁止直接把 Micro 数字当作同等 Vest 数量。

[官方订单说明](https://docs.vestmarkets.com/trading/order-types)：Market / Limit 可在下单表单开启 TP/SL；Scale 不提供该开仓选项。触发价不保证实际成交价，市场锁定也可能阻止执行。浮动盈亏以平台显示为准，不靠模拟价格推断。

下列字符串均为 `data-testid`。查询时必须检查唯一性、可见性、控件状态及所在表单；手机抽屉和弹窗可能产生同名控件。

公开构建引入的 `ui-DRrmzAhi.js` 已静态检查：订单类型和 TP/SL 单位采用同一 Tabs 控件，选中时有 `aria-selected="true"` 与 `data-state="active"`；未选中分别为 false / inactive。当前 Tabs 通过 `mousedown`、键盘或 focus 更新选择，单独的 `.click()` 不足以切换；插件按其事件方式激活，并等待选中属性确认。数量比例的滑块具有 `role="slider"` 及 `aria-valuenow`，可在关闭弹窗内校验是否 100。关闭提交按钮显示最终数量和市场缩写，应与预期持仓数量复核。

主 `order-form` 容器包含数量、单位、TP/SL 及买卖按钮。关闭弹窗是单独挂载的区域，不能复用主表单作用域。`position-row-ID` 只在移动端列表中发现；桌面持仓表可以通过同持仓 ID 的数据与关闭控件关联，不能要求一定存在该行标识。

### 空仓与页面就绪

2026-11-05 核实的公开构建为 [index-C8XU07t1.js](https://next.vestmarkets.com/assets/index-C8XU07t1.js)。顶部账户条容器带 `sticky top-14`，其 `E8e` 展示 Step Goal / Evaluation Goal（阶段目标 / 评估目标）和 Max. Drawdown（最大回撤）的已完成 / 目标或已用 / 上限，部分条目没有 test-id；`ite` 的日亏损保留 `capital-indicator-daily-loss`。插件优先读取顶部条，再使用可见 test-id，忽略隐藏副本、菜单及弹窗；冲突的可见副本视为未知。切换账户后等待账户名称、现金余额和指标稳定，并检测加载标记。读取指标只操作账户选择器，不填写交易表单。

空仓组件没有专用 test-id。英文标题为 `No positions yet`，中文为“未找到持仓”，并附无持仓说明。必须同时确认持仓标签已激活、数据已加载、正确账户仍被选中，以及可见空仓说明。页面没有持仓行、数量标签没有括号、网络断开或 DOM 尚未渲染，均不能单独视为空仓。

货币格式带 `$`、分组逗号及可选正负号；缺失数据可能显示 `-`。不要将占位符、被隐藏数据、无法解析文本或非有限数转换成零。`account-value` 是净值，不能再次把 `account-upnl` 加到它上面。

### 账户指纹

当前账户触发器显示用户设置的账户名（优先本地保存的别名，其次平台名称）和状态徽章。账户 ID 只传入复制按钮事件，未直接显示为 DOM 属性或文本；仅靠触发器不能保证原始 ID 唯一。当前本地服务按完整账户名称全局归并，与浏览器会话无关；类别变化更新同一条记录，执行归属仍由独立会话授权。网页同名项无法唯一定位、账户消失或存在未确认操作时会停止执行。不得把账户类别、列表序号或余额当作平台原始 ID。用户无需手动建立交易绑定。

## 确认弹窗与执行回执

买卖按钮可能直接执行，或依次出现减仓、账户风险限额、滑点/流动性/成本、TP/SL 覆盖、已有关闭委托等确认。**`confirm-order-submit` 属于成本/高滑点/接近限制的警告确认，不是每笔订单必经的普通确认。** 不应默认自动点击它。遇到额外对话框应暂停交由用户处理。

自动处理白名单包含第一阶段完成提示（0.3.16）及已确认关闭账号的亏损上限详情提示（0.3.19）。前者选择平台已准备好的第二阶段账户，后者只关闭信息提示；两者均不代为确认订单、成本、账户购买或实盘激活。

关闭按钮先打开 `close-dialog`；提交后同样可能出现风险、成本或已有关闭委托提示。订单按钮、提示消失或面板关闭不能作为成交证据；应等待平台持仓变化或明确结果。超时后标记结果未知并暂停，先核查页面，禁止自动重复发送。

浏览器 DOM 只能提供当前可见内容。K 线图通常由 canvas 绘制，不能据此声称已导入完整官方历史 OHLC。没有验证过的历史行情来源时，应明确显示模拟行情或本地采集价格聚合的起始时间。

## 自动校验与实页验证边界

1. 每个账户的唯一名称、实际页面语言，以及是否同一登录用户下的子账户。
2. 空仓与持仓状态下各控件是否唯一可见、可解析；是否开启隐私模式。
3. 下单面板为桌面布局还是移动抽屉、数量单位及现有杠杆。
4. 实际 TP/SL 保护是否被平台接受；本地金额监控不能替代平台端有效保护单。
5. 一笔交易从提交到页面结果的变化，以及账户通过、失败、暂停或关闭后的实际状态。
