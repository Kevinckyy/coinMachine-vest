# 成交后止损校验（插件 0.3.28）

开仓表单的 USD 金额可能按提交前行情换算，实际成交均价变化后，原生止损触发价对应的风险未必等于设置金额。过去仅检查止损存在且位于亏损一侧，没有对成交后的金额进行核验。

现在用持仓表同一 position ID 的方向、真实 NQ 数量、成交均价和 `td-tpsl span.text-short` 止损触发价计算风险：多单为 `(成交均价 − 止损价) × 数量`，空单为 `(止损价 − 成交均价) × 数量`。数量已经是 Vest 标准 NQ 单位，不能再乘期货合约乘数；`position-liq-*` 是失败价格，不作为止损价格。

每单使用已固定的 `stop_loss`，包括 Live 独立参数和低回撤不设止损决策。多单理论触发价为 `成交均价 − 金额/数量`，空单为 `成交均价 + 金额/数量`。Vest 的止损编辑器要求触发价为 0.25 的整数倍。插件和后端取最接近的价位，正好在两档中间时选更靠近成交均价的一档。持仓列表读数达到所选价位即通过核验，记录该价位对应的实际风险金额。

金额不符时，打开 `tpsl-edit-open-<positionId>`，核对标题、同持仓成交均价、唯一止损、价格单位、100% 数量和市价触发。只填写 `tpsl-edit-sl-input-0`。提交前后比较所有其他输入与单位，止盈等设置必须保持一致；多级止损、不同数量或未知窗口暂停核对。

`POST /api/bridge/stop-protection` 需要本机配对码、原开仓任务、当前执行会话/授权轮次/账户阶段及新鲜成交快照。后端独立计算价格，在返回一次性提交授权前持久化意图。重复请求不再授权，响应丢失不重提。再次核对身份、数量、均价及价格后只点击一次 `tpsl-edit-submit`；窗口关闭后重新读取持仓表确认。行情已经越过目标止损价时暂停，不把修改当作安全成交。

止损保存失败与开仓失败分别处理：已观察到的真实成交仍存为持仓，任务记为成交确认，保护记录标为失败/未知，冻结账户并暂停新开仓。后端根据原生快照独立计算 `stop_protection.actual_risk`，不信任客户端自报“已校正”。重启保留持仓和修改意图，不重放开仓或止损保存。

验证：`npm run test:stop:browser` 使用隔离的本机数据库和无头 Edge，模拟多空成交偏移、原止盈保留、正确止损不修改、明确不设止损、响应丢失、授权撤销、多级止损及修改期间参数变化，不连接真实 Vest 账户。
