弹窗中的表格是刚结束的考核交易摘要，包含市场、开仓价格、平仓价格、盈亏。顶部未实现盈亏仍残留上一笔金额，本地服务也仍保留旧阶段持仓记录。因此，弹窗出现不能证明页面已选择 Live 账号，交易摘要不能作为 Live 成交回执，后续核对需要独立读取实际持仓与所属阶段。

本机已保存的公开构建 `index-rv9Op3JB.js` 中，这是 `capitalResultModal` 的 `passed` 分支。对应英文文案为 `Evaluation Passed`、`Congratulations - you've passed the Evaluation Phase.`、`Your <Amount /> Funded Account is now live.`、`Go to Funded Account`。标题位于 `dialog-title`；正文使用 `dialog-header` 内普通节点，金额是独立子节点，不能要求整句位于单个文本节点。实页的动态 `radix-*` ID 不宜固定。

该构建中的按钮组件 `O7e` 以当前通过账号的 `evalAccountId` 发起激活流程，并非单纯关闭提示。达到平台 Funded Account 数量上限时，`j7e` 改为禁用的前往按钮，并提供「我理解」/ `I Understand`。未来接入时，应独立识别此二阶段转 Live 弹窗，核对关联 Live 账号、明确阶段和稳定空仓读数，记录一次激活尝试并核对结果，避免重复触发。第一阶段的 `step-status`、准备状态和「开始下一阶段」处理不能直接复用。

随后按用户要求接入插件 0.3.20。执行模式下严格匹配此弹窗，核对当前同名、已通过的二阶段账号后，先在扩展本地持久化激活尝试，再点击一次；新授权、重连或迟到请求不能重放该尝试。禁用或加载中的按钮不点击。

实页继续核对：激活成功仍为同名 Account 26，状态变为「实盘」，平台自动进入 `/portfolio`。插件仅在已保留的激活尝试及原执行轮次下，允许最多 20 秒的资产页衔接；资产页不发送交易请求或伪造 NQ 心跳。通过唯一且同站的「交易」/ `Trade` 导航返回 NQ 后，要求同名 Live 账号的新鲜明确空仓证明，并由服务确认同一账号及 Live 阶段。结果不确定时保留尝试记录，不重复点击；其他账号、未知弹窗或超时停止并记录原因。

服务端在 Live 阶段提交、账号重新发现、参数保存及加载时应用「Live 号默认锁定」。默认开启，`live_default` 锁定不随日切解除；单号手动解锁记为持久豁免。关闭开关仅解除此来源的锁定，手动和交易风控锁定保留。新阶段加回运行池前先应用此规则，已有持仓继续使用原参数。

自动策略的 Live 独立参数为方向、仓位比例、止盈、止损、低回撤不设止损开关及其阈值。初始值为随机方向、25% 仓位、无止盈、130 USDC 止损、低回撤规则关闭、阈值 200 USDC。止盈与止损可留空，低回撤规则开启时须填写止损。参数自动保存，按实际开仓阶段选用，保存表单不改写正在运行的参数或已有持仓。`npm run test:live:browser` 使用隔离页面覆盖激活和资产页返回流程。

2026-11-11 修复插件 0.3.26 的实页兼容问题：二阶段通过时，账号头只显示「已通过」，顶部徽章变成「评估已通过」，不再包含 `2/2`。旧读取器只检查账号头及徽章，导致阶段为未知，拒绝已知激活弹窗并撤销执行权限。现在同时读取当前账号顶部资金横幅中可见的精确「第 2 阶段盈利目标:」标签作为明确阶段证据。只读通过文本或弹窗描述不能推断阶段；徽章与目标阶段矛盾、标签隐藏或来自弹窗时仍禁止激活。新增中英文真实通过徽章回归，验证一次激活、资产页返回、Live 空仓核验及默认锁定。

同次实页验证补充至 0.3.27：激活成功后平台自动导航到 `/portfolio`，桌面页头与侧栏各有一个指向 `/trade` 的「交易」链接。旧逻辑要求链接数量唯一，导致等待超时。现在在同站、已知交易路径和精确文案筛选后，允许多个链接指向同一个完整目标地址，只点击一次；目标地址不同仍拒绝。原生交易导航会回到 `/trade/NQ-PERP`，该页面的同名 Live 阶段、明确空仓、零浮盈亏及新鲜余额读数核验完成前，不能继续策略。相同导航识别用于 Live 利润领取后的返回流程。真实记录和阶段核验保存于本机忽略目录，不纳入 Git。
