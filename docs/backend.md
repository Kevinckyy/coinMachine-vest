# 本地交易服务

Python 3.10+ 标准库实现，无需安装 Python 包。应用仅绑定 `127.0.0.1`，不应转发到公网。

```powershell
python -m server.app
python -m unittest discover -s tests -v
```

默认端口 `8765`，可用 `--port` 修改；SQLite 数据库默认为 `runtime/vest.sqlite`，可用 `--db` 指定。`runtime/` 应被 Git 忽略，其中包含本机桥接配对码和交易记录。不要上传该目录。

## 策略目录与离线回测

`GET /api/strategies` 和 `state.strategies` 提供可选策略。`strategy_id` 随自动策略表单和运行配置持久化；旧配置迁移为 `random_entry`，未知 ID 拒绝运行。

| 路由 | 作用 |
| --- | --- |
| `GET /api/backtests/meta` | 默认账户方案、保存参数、策略目录、缓存清单、报价、任务和最近 50 次结果摘要 |
| `POST /api/backtests/sync` | 提交只读历史导入：`roots/contracts/interval/from/to` |
| `POST /api/backtests/run` | 提交配置并使用本地缓存模拟；接受任务后保存表单，不修改真实策略 |
| `POST /api/backtests/estimate` | `{config,cached_only?}`；复用测时或后台测量一轮，不添加回测结果 |
| `GET /api/backtests/jobs/:id` | 查询导入或模拟的后台状态、进度、错误及结果 ID |
| `POST /api/backtests/jobs/:id/cancel` | 停止本次回测或测时，保留已完成轮次 |
| `GET /api/backtests/batches/:id` | 多轮测试汇总及结果分页，参数 `offset/limit` |
| `GET /api/backtests/runs` | 最近 50 次保存结果的摘要 |
| `GET /api/backtests/runs/:id` | 参数、成本假设、模型版本、逐笔交易、账户、统计、数据指纹及规则出处 |
| `GET /api/backtests/runs/:id/details` | 完整明细分页：`kind=accounts/trades/claims`、`offset`、`limit`（1–500）、可选 `phase` |
| `GET /api/backtests/candles` | 本地行情预览，参数 `symbol/interval/from/to`，最多返回最近 2,000 根 |
| `POST /api/backtests/cost-observation` | 配对插件只读报告 NQ 订单面板报价；需本机配对码及允许来源，时间须新鲜 |

导入及回测仅允许本地界面来源发起，扩展来源只能报告费用观察，不能启动导入或回测。单个服务同时处理一个导入、测时或回测批次；批次内部可并行计算。忙时返回 409 且不覆盖上次接受的参数。异常持久化为任务错误，重启不会自动重跑。后台服务不调用 `Engine` 的开仓、平仓、模式切换或真实队列方法。

配置新增 `rounds`（1–2³²，默认 1）及 `parallel_workers`（1–min(CPU,32)，默认 min(CPU,4)）。多轮任务 `kind=batch`，种子按起始值加零起始轮次、模 2³² 生成。每个子结果 `rounds=1`，带 `batch_id/round_index/duration_seconds`。并行结果在临时工作库落盘，再分批汇入主库；临时目录清理前必须关闭进程及 SQLite 连接。`bt_batches/bt_batch_rounds` 保留批次及全部已完成轮次，`bt_timings` 保留相同参数最近 20 次测时；行情修订标记变更后旧测时失效。批次统计使用 Welford 算法在线累计，不将所有轮次读入内存。取消后为 `cancelled`，重启时未完成批次为 `interrupted`。

模型 v2 的 `account_count` 接受 1–1,000,000 的整数、`"infinity"` 或 `"∞"`（统一保存为 `"infinity"`）；每批最多 10,000。固定池按需实例化账户；无限池在已有可用账户不足一批时补足新号，直到选定区间最后一根可用 K 线结束。移除旧的账户 K 线乘积及 10 万成交上限，只遍历当前持仓并增量汇总统计。完整明细写入 `bt_details`，主结果仅保存最近各 500 条预览及 `detail_counts`。旧 v1 完整 JSON 结果仍可分页读取；模型与随机抽样算法版本分别保存，v2 不保证与 v1 的逐笔随机序列相同。

`server/market_history.py` 的上游地址固定为 `http://127.0.0.1:8090`，方法固定 GET，只允许状态、原生合约目录、解析及历史接口；拒绝重定向、代理和裸根月份回退。历史、任务及结果在独立 `backtests.sqlite` 中；使用 `:memory:` 引擎的测试也使用独立内存缓存。

## 模拟交易

「策略回测」使用独立缓存和计算服务，与本节的工作台模拟账户分开。详见 [策略回测](backtesting.md)。

首次运行创建 8 个模拟账户、14 天示例交易和 240 根模拟一分钟 K 线。每单位价格变化 1 点、数量 1 时模拟盈亏变化 1 USDC；不代表 CME NQ 合约乘数，也不代表 Vest 实际成交、费用、滑点或资金费。所有纸盘数据标记 `mode: paper`。

每账户仅允许一个工具管理的持仓或一个未确认开仓。止盈、止损金额作用于单个持仓。账户累计已实现盈利达到目标后标记通过；账户净值达到配置的最大亏损时纸盘自动平仓并锁定。

## 当日已实现盈亏

账户表另有三项 Vest 页面指标：最大日亏损（已用 / 上限）、最大回撤（已用 / 上限）、阶段目标（已完成 / 目标）。`capital_metrics.daily_loss/drawdown/goal` 分别保存 `text/current/limit/percent/observed_at/category/source/update_pending`；每项有独立时间戳。页面只显示比例时仅保存 `percent`，金额未知；主账户或某阶段未显示的指标保持未知，不以零代替。

每次只更新实际读取到的指标；缺失时保留旧值与旧时间戳，并标记 `update_pending`。迟到的旧读数不会覆盖更新读数，同名归并逐项保留最新观察，SQLite 重启仍保留。阶段改变后旧指标仅保留在旧阶段账本；新阶段尚未读到的指标显示未知，不跨阶段借用。三项直接读取 Vest 的口径，用于展示；不替换本地 `profit_target/max_loss` 配置，也不按下述 17:00 区间重算平台日亏损限制。

`GET /api/state` 的 `trading_day` 提供 `start/end`（UTC Unix 秒）、`label`（结束日的纽约日期）、`timezone: America/New_York` 和 `cutoff: 17:00`。按用户指定的纽约每天 17:00 连续日切，不套用北京时间零点或交易所节假日日历。区间起点包含、终点不包含，未来时间的平仓记录不计入当前值。

每个账户增加 `daily_realized_pnl` 和 `daily_trade_count`，仅按相同 `account_id/mode/phase`（未知阶段旧记录不补猜阶段） 的持久化平仓历史汇总；余额变动、未平仓浮盈亏及待确认任务不参与。已关联账户没有当日记录时为零，未关联观察行显示未知。口径只覆盖本工具已记录的历史，不代表自动补全的 Vest 全量历史。

`server/trading_day.py` 优先使用系统 IANA 纽约时区。标准库 Windows 环境缺少时区数据库时，使用自 2007 年实施的美国夏令时规则，分别计算两个 17:00 端点，因此切换日可为 23 或 25 小时，依据 [NIST 夏令时说明](https://www.nist.gov/pml/time-and-frequency-division/popular-links/daylight-saving-time-dst)。不额外安装 Python 依赖。

## 随机批次

### 主账户永久只读

账户名称精确匹配「主账户 / 主账号」（含繁体）或 Main / Primary / Master Account，或页面类别为 `default/main/primary/master` 时，持久化 `execution_excluded: true` 和原因。曾识别为主账户的记录，即使后续类别变化或同名合并，仍保持永久排除。`enabled` 固定为 false，策略锁没有 `strategy_unlock_at`，启用 / 解锁接口不能覆盖；普通账户的每日解锁规则不变。

后端在手动 / 批量 / 策略开仓、平仓（包括全部平仓及保护平仓）、任务创建和派发、百分比数量确认入口排除主账户。历史未派发的开仓和平仓取消，已派发或未知任务及旧持仓保留用于人工核对，已派发回执仍可记录事实，绝不因排除而伪造平仓或丢弃实际回执。插件再次检查路由账户、任务配置和当前页面主账户身份，禁止填写交易表单及开平仓点击；只读扫描、余额、浮盈亏和历史展示继续工作。

### 默认保护与每日开仓额度

新请求的 `take_profit` 可为 `null` 或省略，`stop_loss` 缺省为 130；界面新订单固定不设置止盈。旧订单和明确指定的正止盈金额仍兼容，以免改变已有仓位保护。插件先清空旧止盈，再填写止损；无 TP 订单必须观察到原生 SL 且没有原生 TP，才确认开仓。保留已有的数量、方向、品种及持仓 ID 核验。

`daily_entry_used` 根据当前美东 20:00 区间中的持仓 / 历史 `opened_at` 及开仓任务 `delivered_at` 计算。手动与策略开仓共享每日一次限制，后端在入队、实际派发及页面数量确认时核验。未派发取消不占额度，已派发结果未知或人工核对后仍保留本日占用；服务重启和策略重启不能清除。历史按开仓时间计额度，按平仓时间计当日已实现盈亏，不能混用。

所有交易确认结束后都会策略锁定，包括手动结束、原生止损与目标平仓。解除锁定仍受每日额度约束；除主账户永久排除外，所有本地策略锁在下一次美东 20:00 自动解除，不自动加入当前策略。平台外未记录的开仓无法用本地记录证明额度使用情况。

`_position_exit_reason` 在明确已通过或已知目标达到时生成 `target` 平仓；不猜测自动发现账户的未知目标金额。若平台在平仓任务尚未派发前自行平仓，取消该未派发任务并结算实际空仓观察，避免重复平仓。已通过账户关闭现有仓位时不要求开启新的下单表单，但仍核验账户身份及精确持仓，并仅使用对应持仓的全量关闭控件。

每次运行从所选可用账户中随机选择完整的 n 个账户，逐个提交；账户之间使用配置区间的均匀随机延迟。整批全部确认平仓后，再计算随机批间延迟。下一批不会复用本次运行已经选过的账户；剩余账户不足 n 个时运行结束。最后一批完成后也会经过配置的批间等待，再判断账户池已用尽。

策略前端使用 `size_percent: 25 | 50 | 75 | 100`（仓位大小），与固定 `quantity` 互斥。浏览器开仓任务最初只有比例，不预估数量；扩展在主表单点击同档 `size-pct-*` 按钮，核对比例滑块并等候页面数量稳定后，调用 `POST /api/bridge/size` 固定本任务实际 `quantity`，随后才允许点击开仓。该接口要求配对码、当前执行会话 / 版本 / 账户身份、已派发且未过期的百分比任务及新鲜明确空仓快照；已固定数量只接受相同的重复确认，不能改量。接口不下单、不派发其它任务，不延长执行许可。

成交回执仍严格核验真实持仓方向、ID、品种和已固定数量，未先确认数量或成交数量不符时记为未知并锁定，不猜测成交。持仓记录保留 `size_percent` 和实际 `quantity`；后续止盈止损与全量平仓使用实际数量。旧固定数量策略请求仍兼容。模拟百分比策略明确使用 `净值 × 比例 ÷ 模拟价格` 的 1 倍无杠杆数量，不用于推算浏览器账户。

停止策略取消尚未送达浏览器的策略开仓，不主动平仓；已建立持仓继续受止盈止损保护。紧急全部平仓会先停止策略，再逐个处理持仓，并返回逐项错误，不能把失败当作全部平仓成功。已送达浏览器的动作不能撤回，必须等待观察确认。

### 账户策略锁定

账户持久化 `strategy_locked`、`strategy_lock_reason`、`strategy_lock_source` 和 `strategy_locked_at`。`POST /api/accounts/:id/strategy-lock` 接受严格布尔值 `{ "locked": true | false }`，只允许本地前端调用。锁定独立于账户的风险状态和插件执行权限，仅阻止后续自动策略开仓；手动下单仍须满足原有账户风控和执行条件。

手动锁定立即移出当前策略的剩余账户池和待提交列表，并取消该账户尚未派发的策略开仓。已派发动作、现有持仓、平仓及保护任务继续核对与处理。解除策略锁定不会清除风险锁定，也不会重新加入当前运行；下一轮需重新选择。

评估已通过时自动锁定，且取消该账户所有尚未派发的开仓。策略持仓触及 TP/SL 时锁定：纸盘在成交时记录，浏览器在观察到阈值并创建保护平仓任务时即记录，不等待回执。浏览器原生平仓后也根据已确认的余额变化及原因识别 TP/SL；无法确认原因时记为 `external_close`（策略持仓结束），仍锁定避免再次自动开仓。手动与自动交易确认结束后均触发策略锁定。来源包括 `manual`、`external_close`、`daily_completed`、`target_reached`、`take_profit`、`stop_loss`、`evaluation_passed`，评估通过原因优先保留。

策略锁在同一交易日跨服务重启及新策略运行保留，下一次美东 20:00 全部自动解除。平台通过 / 失败、风险锁及未知操作状态不重置；已通过账户仍不能开仓。批次屏障仍等待该批策略持仓与未确认动作全部结束，锁定不会把尚未平仓的账户当作完成，之后在剩余未锁定账户中选择下一批。`state.accounts` 的 `strategy_executable` 表示自动发现的浏览器账户可执行且未策略锁定，`executable` 继续表示原有手动执行条件。

### 已取消预备窗口

不再保留或预读下一批名单，只在当前批次已确认结束并经过随机间隔后选择下一批。前端预备面板及扩展开窗、预备读取循环已移除；旧 `preparation` 响应固定为 `active: false`，兼容接口不改变账户、权限或任务。升级时关闭已保存的旧专用窗口；无法关闭的旧 URL 标记窗口保持只读，不会提升为执行。

### 次日自动解锁

`_roll_strategy_locks` 使用美东 20:00 日切，定时 tick、状态读取、资格核验及服务启动会补偿过期锁。除主账户的永久排除外，本地策略锁在下一次日切自动解除，并清空锁原因与时间；`strategy_unlock_at` 提供预计时间。不会清除平台 passed/failed、风险锁、已有仓位、每日已派发记录或未知操作，也不会自动恢复策略或插入当前批次。

## 浏览器桥接

不调用或猜测 Vest 私有 API，不保存密码、会话 Token 或私钥。浏览器扩展使用本机配对码访问受保护的桥接路由，配对码保存在当前数据库。`GET /api/bridge/config` 仅允许本地前端读取，禁止扩展来源。`GET /api/bridge/accounts` 允许持有码的扩展读取浏览器账户 id/name 等信息。

### 无绑定的账户发现与插件模式

新版流程无需手工创建浏览器交易账户、选择绑定记录或填写账户本金。扩展读取页面账户列表后调用 `POST /api/bridge/session`，自动生成 `auto_discovered: true` 的账户；插件中唯一的 `readonly / execute` 模式开关决定是否允许执行。自动账号以完整账户名称全局唯一，不以浏览器或会话分组，ID 不是 Vest 原始账户 ID。读取同名账户复用原 ID，类别更新也不新增记录；原 ID 随迁移保留，新记录使用完整名称的哈希。网页同一列表确有同名项时，显示合并为一行，但因无法唯一定位而禁止执行。类别从 Evaluation 变为 Passed 时保持本地 ID，平台通过或失败状态不能用于继续开仓。旧手工浏览器记录及历史保留，升级后禁用并标记 `legacy`，不作为新执行入口。

`initial_balance` 仅在首次有效现金读数出现时记录，`baseline_source: first_observed` 表示资金变化的观察基准，并非平台考核初始本金。平台利润目标与最大亏损没有可靠读数时为 `null`，不会套用纸盘的 8% / 5% 或手工初始值。单笔订单仍须有明确的止盈、止损金额。未读取的金额和基准均保留 `null`。

会话请求包含 `session_id, mode, mode_epoch, tab_url, accounts`。`mode_epoch` 是插件持久化的非负递增整数；较旧版本的控制消息返回 409。同版本可收紧到只读，但不能提升到执行。只有用户实际切换至执行时发送 `authorize: true` 且版本高于之前值，才授予执行许可；正常心跳不带授权。执行许可 30 秒未续期、服务重启或未知成交结果会自动降为只读，之后的旧执行心跳不能自行恢复。

`/session` 返回 `mode, mode_epoch, accounts, next_account`。入池和排队只要求有效执行许可及可靠账户身份，不要求所有子账户在同一秒同时显示。开关预检只检查页面连接和当前账户身份；即使当前查看主账户或没有开仓表单，也能开启其它账户的执行许可。空闲时 `next_account` 为 null，只读更新当前账户，不轮巡或准备表单。有排队任务或工具持仓时才返回目标，`operation` 为 `open/close/monitor`；关闭及监控只要求持仓面板，无需开仓表单。目标指定并未派发动作：扩展切换该账户、自动核对身份和页面后，再向 `/bridge/poll` 发送 `session_id, mode_epoch, account_id, identity` 和 5 秒内的新鲜快照；只有这一步才能领取一次实际任务。同一会话仍有已送达或结果未知的动作时，不再路由或派发其它账户。心跳可附 `heartbeat_only: true`，只续期和同步观察，不推进账户轮巡或返回下个目标。

插件在 `chrome.storage.local` 独立保存最近执行错误，观察更新和重新打开弹窗不会清除，下一次成功开启后清除；配对码从错误消息中脱敏。迟到的旧模式错误不能撤销较新许可。内容脚本握手同时核对协议及扩展版本，旧脚本先升级再执行业务消息。

下单前自动选择 USD 止损金额模式及 Micro 数量模式，分别检查 Tabs 的选中属性与数量选择器的 `data-unit`；不会跳过校验。NQ 输入 1 Micro 为 2 Vest 单位，微型必须为整数。浏览器手动输入在前端转换成 Vest 数量；百分比策略读取页面的 Micro 整数结果后转换，再通过 `/bridge/size` 固定 canonical Vest 数量。持仓、历史、成交回执与 API `quantity` 保持 Vest 单位，平仓弹窗的最终确认量也按其显示的 Vest 数量核验；旧 Token 适配保留用于历史兼容。配置、填单、比例选择和提交前均检查单位，不允许跨单位直接比较裸数字。

执行失败撤销时可附 `execution_error`（最长 500 字符），服务脱敏后记录到会话及策略暂停日志，让工作台显示具体失败原因。未派发的请求取消且不占本日开仓额度，恢复许可不会自动启动策略。

切回只读立即取消此会话尚未送达的开仓及平仓任务，暂停相关策略，不主动平仓；已送达任务不能撤回，但其真实回执即使带旧模式版本仍可用于记账，不能重投。原生页面止盈止损仍须在 Vest 保持有效。`state.accounts` 提供 `execution_mode, executable, auto_discovered, category, identity, session_id`；`executable` 用于下单账户选择，`snapshot_ready` 单独表示此刻 5 秒内的页面检查。资金读数过期时仍显示未知，不用执行许可伪造实时盈亏。

### 全局同名归并与执行归属

服务启动时 `_deduplicate_browser_accounts` 按完整名称归并旧自动发现记录，不受 `account_scope/session_id` 影响。旧副本标记 `merged_into` 并保留原数据，状态 API 仅返回保留记录；历史、任务、持仓、策略列表及会话账户列表中的旧 ID 指向保留 ID，并追加归并审计。保留最早资金基准、最新完整资金快照及其实际读取时间，保留锁定 / 风险状态；冲突的已知风险阈值取较严格值。多个旧副本都有持仓或未确认任务时，仍合并显示并保留全部仓位 / 任务，同时锁定等待核对。

执行权限仍按标签页会话授权；账户只有一个执行归属。另一个浏览器只读读取不抢占有效执行会话，也不会撤销其任务；同名账户存在有效执行者或其他未确认操作时，拒绝第二个执行授权。原会话切回只读且没有未确认任务后，新的显式授权才可接管；接管时废弃旧交易就绪快照，仍须新鲜页面核验。原任务的回执继续按原 `job.session_id` 校验，旧别名仅可用于对应回执归档；旧别名不能继续发起新订单。

### 独立只读账户同步

只看真实账户列表和余额时，不必手工创建可交易账户或开启执行授权。扩展配对后通过 `POST /api/bridge/observe` 发送 Vest 页面中读取到的账户名称、类别、净值、浮动盈亏及每行的实际读取时间；前端读取 `GET /api/account-observation`。该数据独立存入 SQLite 的 `read_only_observation`，不会调用交易桥接、创建交易账户、认领外部持仓、锁定账户或改变策略与订单。

观察路由要求 `X-Bridge-Token`，接受 Vest 的 NQ 显示路径 `/trade/NQ-PERP` 及内部市场路径 `/trade/NDX-USD-PERP`；其他来源与品种仍被拒绝。GET 观察结果只提供本地前端，不向扩展来源开放。首次尚未连接时列表为空，不把之前手填的初始余额当成真实读数。金额严格接受有限数字或 `null`，未知不补成零；只有净值和浮盈亏均已读取时，才以二者差值核验或计算余额。余额不一致时保持未知并附 `read_error`。

账户记录的 `key` 由名称、类别和同名扫描序号生成，是本工具的显示键，并非 Vest 账户 ID，不能用于下单。读取接口保留同名扫描条目的原始观察并标记 `ambiguous`，账户及前端显示按完整名称归并一行；执行不猜测应选择哪个网页条目。未读取账户的 `observed_at` 为 `null`；切换读取过的其它账户使用其原有时间，心跳不会刷新缓存读数。扩展可附扫描 `progress`（`completed/total/name/done/restored`），只供显示进度。

连接或某行读取超过 30 秒后，该行标记 `stale: true` / `update_pending: true`，主要金额保留最后一次真实观察，`observed_at` 保持原读取时间；`observed_equity/observed_balance/observed_unrealized_pnl` 兼容保留。没有有效读取时间或从未读到的金额仍为 `null`。服务重启后保留账户名称和最近快照，连接先重置为断开，前端显示缓存和「待更新」，直到扩展发送新观察。

`state.accounts` 的自动发现账户同样保留上次金额和风险 / 通过 / 策略锁定状态，以 `data_stale/update_pending` 标记待刷新。显示缓存不修改 `_fresh/_ready` 的 5 秒执行检查和 30 秒权限心跳，不更新读取时间、不授权执行，不将缓存作为实时风险或成交证据。

桥接每次上报账户 id、`https://next.vestmarkets.com` 页面 URL 和快照。观测模式可更新真实余额、浮盈亏与观察价格；执行还要求扩展显式 `ready: true`。快照必须含余额、浮盈亏、价格、明确的空仓/持仓状态，且接收与观察时间都在 5 秒内。账户净值与浮盈亏读取口径由扩展校准，`balance` 应为 `equity - unrealized_pnl`，不能把净值当现金余额。

开仓要求页面明确空仓。动作仅投递一次，开仓结果只有在观察到持仓、真实入场价、平台持仓 id、方向和数量与请求一致时才确认。平仓动作携带平台持仓 id，再次核对 id/方向/数量，不能关闭另一个仓位。额外风险弹窗、页面变化、读数错误或超过 30 秒无结果均锁定账户、暂停策略、取消其他尚未发送的开仓，不自动重试。已经送达的其他动作仍需观察核对。

浏览器模式仅从连接后有效页面读数聚合独立的一分钟 OHLC，最多保留 720 根；这是本机观察采样，不是官方历史 K 线，不补齐断线期间数据，成交量设为 0 表示未知，也不使用纸盘价格代替实盘价格。实盘历史仅记录此工具观察确认的交易，不伪造平台接入前历史。入场价来自平台持仓，退出价是平仓确认时页面观察价，并非成交回报；已实现盈亏为开平仓期间观察到的现金余额变化，包含费用、资金费或期间其他资金变动，不能当作独立交易的精确成交损益。记录以 `price_source`/`pnl_source` 标明口径。

断线后账户表保留最后观察到的浮盈亏并标记待更新；持仓实时标记价格和浮盈亏仍显示不可用，后端不推算真实损益。原生页面止盈止损是浏览器断线期间的保护来源。服务重启暂停原运行策略，保留纸盘持仓及保护；未确认浏览器操作保持锁定，不能重投。出现未知结果时应到 Vest 核对并处理实际仓位，不能通过重复点击或重发旧请求消除不确定性。

完成 Vest 页面人工处理全部实际持仓和挂单后，可以使用前端“人工核对”按钮解除操作未知状态。对应 `POST /api/bridge/reconcile` 请求需 `account_id` 和 `acknowledge: true`，只接受本地前端来源，不允许扩展调用。必须有 5 秒内有效的明确空仓读数、零浮盈亏，且不存在尚未超过 30 秒的已送达操作。原本地持仓只归档到审计记录，不生成猜测成交、价格或盈亏历史。根据真实余额重新计算账户风险和通过状态，策略保持暂停/停止，必须人工重新启动；达到最大亏损的账户仍保持锁定。

对于用户明确确认评估失败、且已从页面列表消失或页面已标记失败的考核账户，本地管理端可在同一路由提交 `terminal_status: "failed"` 和 `acknowledge: true`。必须先停止策略，不得有本地持仓或 30 秒内已派发的操作。该操作将旧异常请求归档为 `archived_failed`，保存原始账户、请求和用户确认来源到审计记录，永久停用该号，并解除这条旧异常对其他账户的阻塞。它不代表成交或空仓确认，不刷新最后余额和观测时间、不生成盈亏历史、不恢复策略；已派发请求仍占用当日开仓次数。停用标记跨日、重启、同名合并和浏览器重读均保留，不允许删除后重新启用；主账户不可使用此途径修改。

自动失败处理：`bridge/session` 接收唯一完整账户名及 5 秒内的明确 `failed` 类别。状态有独立 `status_observed_at`，不借用旧余额时间；旧插件省略时回退到该行 `observed_at`。旧或重名证据不得自动终止账户，仅菜单消失也不得推断失败。确认后记录 `failure_confirmation_source: platform`，终止此号未完成任务并审计留存本地持仓；原始任务、仓位、页面证据全部保留，不伪造成交或损益。已结束任务的迟到回执只留存，不再恢复仓位。此处理不撤销其他账号的执行许可、不恢复已暂停的策略；正在运行的策略继续等待同批其他账号结束，再按原随机间隔推进。

原生爆仓后的账户徽标使用 `Closed / 已关闭`，也作为明确终止状态处理，保留 `terminal_status: closed` 和类别 `closed`，不将其改写成失败原因。当前账号即使已从菜单或扫描缓存消失、金额被隐藏，也能仅凭当前账号名称及稳定的终止徽标同步此状态，完成自动停用、归档并移除旧任务阻塞；无需先尝试下单表单或人工核对。新发现的当前账号保留实际徽标类别，不能无条件覆盖为 `unknown`。旧版本已留下 `unknown` 且锁定的记录，用户明确确认失败后可手动归档，仍要求策略停止、无本地持仓且无 30 秒内已派发操作；健康、主账户与没有用户确认的账号保持禁止归档。

`POST /api/accounts/:id/archive`（本地前端来源）需 `acknowledge: true`。普通手动归档适用于所有已读取的非主账户，包括正常账号，记录 `archive_kind: manual`、`archive_source: user`；保持平台类别、风险状态、金额和历史不变，仅归档并停用、移出剩余策略池和下单队列。可取消尚未派发的开仓，存在本地/页面已知持仓、已送达或结果未知交易时拒绝；不暂停策略、不撤销其他账号的执行许可。审计保留原账号及取消的排队任务。归档账号跨日、重启、同名合并和重新读取后仍不可启用或执行。

已确认失败的账号仍可直接归档（`archive_kind: terminal`）；无终止证据的锁定旧账号，需要额外显式提交 `terminal_status: failed` 才走上述用户确认失败条件，普通手动归档不会代替这项确认或清除未知交易。主账户保持只读展示，不允许归档。`POST /api/settings` 可单独更新布尔项 `auto_archive_failed`（默认 true，不影响交易模式），开启时也归档已停用但尚未归档的失败账号。`GET /api/state` 保留全部账户和历史，返回 `preferences`、账户 `archived` / `archived_at` / `archive_source` / `archive_kind`；前端默认隐藏归档记录并排除策略池，可勾选显示。关闭自动归档仍必须自动停用并结束已证实失败的账号；原先手动归档的账号不会因平台后续失败而重新出现。

## 主要接口

- `GET /api/state`：完整账户、持仓、历史、日志、行情与策略快照；前端按 `mode` 过滤账户/持仓/历史。
- `POST /api/accounts`，`POST /api/accounts/:id/toggle`，`DELETE /api/accounts/:id`。
- `POST /api/accounts/:id/strategy-lock`：`locked: boolean`；设置策略排除状态，不修改风险锁定或插件权限。
- `POST /api/orders`：`account_ids, side, quantity, take_profit, stop_loss, symbol, idempotency_key`。同一幂等键和内容返回原结果，不能用于不同内容。
- `POST /api/positions/:id/close`，`POST /api/positions/close-all`。
- `POST /api/strategy/start`，`POST /api/strategy/stop`。
- `POST /api/strategy/config`：保存自动策略表单参数，返回完整已验证的参数；不需要账户选择、连接或执行权限，不启动策略、不修改本轮运行配置，扩展来源不能调用。参数存入 `preferences.strategy_config` 并随 `GET /api/state` 返回；缺少旧偏好时从最近运行配置迁移，不自动恢复交易。账户池选择不属于执行参数。
- `POST /api/settings`：`mode: paper | browser`；仍有持仓或未确认动作时不能切换。
- `GET /api/history.csv?account_id=...&days=...`：导出当前模式历史，UTF-8 BOM；名称经过 CSV 公式注入防护。
- `GET /api/bridge/config`：本地配对配置。
- `POST /api/bridge/observe`：独立只读账户观察，要求 `X-Bridge-Token`，允许已配对扩展来源。
- `POST /api/bridge/session`：自动发现账户、插件模式版本与许可心跳、选择下一个页面目标，要求 `X-Bridge-Token`。
- `POST /api/bridge/preparation`：已停用的兼容接口，固定返回未激活，无副作用。
- `POST /api/bridge/inspect`：带配对码的当前账户只读快照，为用户显式人工核对提供新鲜证据，不派发、不记成交、不更新许可。
- `POST /api/bridge/size`：百分比开仓前确认页面计算数量；`job_id, account_id, session_id, mode_epoch, identity, size_percent, quantity, snapshot, tab_url`，要求 `X-Bridge-Token`。
- `GET /api/account-observation`：本地前端读取真实页面账户列表与金额观察，拒绝扩展来源，不使用手填交易余额。
- `GET /api/bridge/accounts`，`POST /api/bridge/poll`，`POST /api/bridge/result`：要求 `X-Bridge-Token`。
- `POST /api/bridge/reconcile`：人工处理后恢复账户，拒绝扩展来源。

POST 只接受 JSON 对象，最大 64 KiB。所有入口核验本机 Host/Origin；错误返回 `{error: "..."}` 与相应 HTTP 状态。HTTP 服务也可在构建完成后直接提供 `dist/` 前端。

### 未知订单与只读核对

持仓的 `NDX-USD-PERP` 原生链接与 NQ 名称规范为内部 `NQ-PERP`；链接来源、白名单路径、持仓 ID、方向及数量仍严格校验。正常确认的持仓在原生止损后读取到明确空仓，记录资金变化并锁定账号；整批结束及间隔到期才启动下一批。

历史已派发而未知的操作不会被新适配器推测成成交或平仓。手动新下单及新策略启动前检查所有未确认浏览器操作，明确报告阻塞账户，禁止继续排新请求。`bridge_inspect` 只写 `ready: false` 的当前账户快照；同一执行归属或已登记且原归属不活跃的只读观察才能使用，账户名、页面、品种、时间和金额关系必须一致。它不解决未知状态、不改变账户归属、不续期许可。人工核对仍要求用户确认及新鲜明确空仓，保留已派发的本日额度、平台 failed/passed 等限制及审计记录；不虚构成交或盈亏历史。


## 阶段账本与每日额度

`phase` 仅接受 `1/2`、`2/2`、`live` 或未知。插件从当前账户徽标及第二行顶部条的可见阶段徽标读取，忽略账户名及普通百分比；`phase_observed_at` 必须是有效且新鲜的时间戳。服务只接受向前切换，迟到的上一阶段、未知阶段及旧客户端不得覆盖已知当前阶段的资金。

账户持久化 `phase_books[phase]`，独立保存资金基准、最后资金读数、`capital_metrics`、目标和风控信息；订单、持仓和已确认历史均带 `phase`。返回的阶段账本附已记录的历史盈亏及笔数、当日盈亏和每日额度使用情况。平台风险原值与工具已确认的平仓盈亏分开显示，缺失历史不推算。`phase_realized_pnl` 与当前阶段的 `daily_realized_pnl` 不包含旧阶段记录。

每日额度按账户、阶段、美东20:00区间核验。首次识别已有账户阶段时用 `legacy_phase_scope` 保守承接尚未分阶段的旧每日占用，但不修改这些旧交易的财务阶段；下一阶段独立获得新额度。真实向前切换会清除上一阶段的自动锁定，手动锁定、归档、失败停用与主账户永久排除保留。仍运行的策略可将原选中账户的新阶段加入后续批次，遵守批次结束及随机间隔；停止、暂停和已完成策略不会自动恢复。

若有旧持仓、外部持仓或已派发/未知请求，先设置 `phase_pending`，仅安排只读同步。切换要求同一当前账户提供新阶段的新鲜、明确空仓、零浮盈亏、余额一致且报价有效的 `phase_snapshot`；否则保留旧仓及额度并禁止新开仓。确认后旧未派发任务取消，已派发异常标记 `archived_phase`，旧本地持仓保存在阶段变更审计，不补造平仓或损益，旧账本标记 `settlement_pending`。迟到回执只留审计，不能重建旧仓。

已知阶段的 `poll` / `size` / `result` 必须携带匹配阶段的页面快照；执行会话也需报告同一阶段。重启不恢复交易授权，未知阶段的旧客户端仍能保留最后读数，但无法执行已分阶段账户的任务。


## 剩余最大回撤与条件止损

策略表单及运行配置包含 `skip_stop_loss_on_low_drawdown`（布尔，默认 false）和 `drawdown_stop_loss_threshold`（正数，默认 200）。配置中的 `stop_loss` 始终保留填写的正金额。浏览器每次开仓使用当前账户、当前阶段且 5 秒内的 `drawdown.current / drawdown.limit` 绝对金额；`remaining = limit - current`，严格小于阈值才省略止损。未知、仅百分比、待更新或阶段不符的指标不得用于派发，尚未派发时不占每日额度。

按比例开仓的 `/api/bridge/size` 同时接收 DOM 新鲜 `drawdown` 及 `stop_loss` 决策，服务再次校验并将实际止损和数量共同固定在已派发任务上，回传同一决定。扩展清空旧止盈、按决定清空或填写止损，提交前再检查实时回撤条件及输入值；条件跨越阈值时停止，不能修改已确认决策或重复下单。不设止损的成交仍要求同一持仓 ID、方向、数量及可见 TP/SL 单元格明确无止损，隐藏、缺失或平台仍存在止损均不算确认。

确认后的持仓 `stop_loss` 可为 null，同时保留 `configured_stop_loss`、`stop_loss_omitted`、`remaining_drawdown_at_entry` 和阈值供审计；本地止损退出及止损锁定均按实际止损处理，不能沿用被省略的配置金额。账户级风控和目标退出保持有效，手动交易仍要求正的止损金额。模拟账户用明确配置的最大亏损加净值与基准差计算，不使用或伪造平台读数。

开仓额度及策略锁使用独立的 `entry_day`（美东 20:00），`trading_day` 的当日已实现盈亏仍为美东 17:00。两种窗口分别计算夏令时端点。自动策略优先抽取可交易 Live 账号，同阶段随机选择；批内 Live 先提交。
