# VEST Control

面向 Vest Capital 的本地多账户交易管理工具，包含 React 前端、Python / SQLite 交易服务及 Chrome / Edge 浏览器桥接扩展。默认运行模拟交易，无需 API；回测的 PCG64DXSM 随机数生成器使用 NumPy。

## 启动

需要 Node.js 22+、Python 3.10+，并确保 `node`、`npm`、`python` 已加入 PATH。在项目目录执行：

```powershell
npm install
python -m pip install -r requirements.txt
npm run dev
```

打开 **http://127.0.0.1:5173**。首次运行生成 8 个模拟账户、14 天示例盈亏记录和模拟行情。模拟数据始终标注，不与浏览器数据混用。

也可以先构建，再通过一个 Python 服务同时提供界面和 API：

```powershell
npm run build
python -m server.app
```

此时打开 **http://127.0.0.1:8765**。如希望恢复干净的模拟数据，请停止服务后备份并另指定数据库：`python -m server.app --db runtime/new.sqlite`。开发前端固定代理 8765；修改后端端口时也需调整 `vite.config.ts`。

## 功能

- 账户扫描按单账号超时：插件内可设置并保存，默认 3 秒（0.5–120 秒）；取消整轮 45 秒上限，超时账号记录失败后继续。扫描加快稳定性检测，分别展示成功、失败、未读数量，并支持停止读取及恢复原账号。

- 同批同品种统一方向：随机方向每批只抽一次并持久保存；考核号与 Live 同批时合并固定方向要求，冲突则整批暂停。开仓排队及浏览器领取前均校验，执行页明确提示并显示当前批次方向；回测同步使用此规则。详见 [批次方向规则](docs/batch-direction-policy.md)。

- Live 自动策略：考核通过后单次点击激活并返回交易页核验；可默认锁定新 Live 号，逐个手动解锁。Live 独立配置方向、仓位、止盈止损及低回撤规则，参数持久保存。详情见 [Live 阶段处理](docs/vest-live-transition-capture.md)。

- 工作台：账户总净值、已实现 / 未实现盈亏、账户目标进度、浮盈浮亏监控。
- 多账户管理：真实账户自动从浏览器发现并选择账户池，表格包含按平仓历史统计的当日已实现盈亏；模拟账户支持新增、启停、删除及独立利润目标和最大亏损。
- 主账户永久排除：主账户 / 默认账户仅展示余额与盈亏，禁止手动、批量及策略开仓和平仓，不参与任何策略执行。排除持久化保存，不随美东日切、浏览器切换、重复读取或重启解除。
- 阶段账本：页面识别 `1/2`、`2/2`、`live`，账户表点击阶段可查看各阶段独立的盈亏、最大日亏损、回撤和目标。历史交易及 CSV 保留所属阶段，未知阶段的旧记录不猜填。
- 账户指标：从 Vest 页面左上角读取最大日亏损、最大回撤、阶段目标，展示已用 / 上限或已完成 / 目标；三项分别缓存并标记待更新，未读到时显示「—」。
- 交易台：NQ-PERP 交互式 K 线（1 / 5 / 15 / 60 分钟）、市价多空、批量下单、逐仓或全部平仓。
- 盈亏分析：本工具交易历史、按账户 / 时间 / 盈亏过滤、累计曲线及 CSV 导出。
- 自动策略：当前策略以「随机下单」选项提供，使用共享策略目录，后续可增加其他策略。每批随机选 n 个账户，每个账户之间均匀随机延迟；本批持仓全部结束后，再随机等待进入下一批。仓位大小（25% / 50% / 75% / 100%）、方向及每账户止损金额可设置；默认止损 130 USDC，不设置固定止盈。
- 策略回测：从本机 8090 数据桥只读拉取 MNQ、MES、MGC、MCL 月份合约并独立缓存；另已下载并构建 2019–2026 年 MNQ 一分钟连续后复权数据，可跨季度回测。选择已有策略及参数，按当前账户方案模拟两阶段评估、风控与分润；支持 10,000 个账户、∞ 持续补号、多轮种子及多核并行，提供单轮 / 总耗时预估。页面仅显示多轮统计，包含阶段 / 每号平均单数、平均持仓时间和最好 / 最差 / 平均资金曲线；可切换含交易手续费与零交易手续费重算曲线。参数、完整明细、成本假设及结果持久化；详见 [回测说明](docs/backtesting.md)。
- 交易时间统计：回测及历史详情支持24小时平均开平仓次数、按开仓时点的平均持仓时间，以及小时 / 星期 / 每周 / 每月的胜率和净盈亏分布；可切换美东、北京时间及自定义 UTC±N 固定偏移，并选择轮均与日均口径，并分页查看开平仓时间记录。
- 策略参数自动保存到本机 SQLite：修改后即保存，无需启动策略；刷新页面、重开浏览器或重启服务后恢复，旧版本首次升级沿用最近一次已启动策略的执行参数。保存表单不修改正在运行的策略，也不自动启动、恢复或授权交易。
- 回测历史：独立管理页，按“策略名-自定义名称-北京时间戳”命名，支持品种、策略、创建时间 / 行情区间及名称正则组合筛选、分页、重命名。选中记录可查看汇总统计、资金曲线和完整参数，历史结果原样保留。
- 可选「剩余最大回撤小于阈值时不设置止损」：默认关闭，阈值默认 200 USDC。开启后每个账户每次开仓前重新计算；浏览器账户使用当前阶段页面「回撤上限 − 已用回撤」，严格小于阈值时清空止损，等于或大于时使用填写的止损金额。读数缺失、仅百分比、过期或阶段不符时不派发；数量及止损决策由服务确认后固定，提交前条件变化则停止。本地该笔持仓也不使用原止损金额触发平仓，账户原有风控与目标仍保留。模拟账户按配置最大亏损与资金、净值差计算。
- 策略锁定：在账户列表或策略账户池中锁定 / 解除锁定，排除指定账户的自动开仓；通过评估或策略持仓触及止盈 / 止损时自动锁定，并显示原因。
- 浏览器桥接：观察真实页面账户净值、浮盈亏和报价；插件的只读 / 执行开关是唯一交易执行入口，控件自动准备并校验。

每次策略运行在同一阶段不重复使用已选账户；原账户进入新阶段后可重新加入当前运行的后续批次，仍遵守批次等待与随机间隔；账户池不足完整一批时结束。已达到本工具配置利润目标或触及最大亏损的账户不再开仓。手动停止只停止后续开仓，原有持仓仍按止盈止损管理；全部平仓会先停止策略。随机延迟用于批次调度。

账户以**完整名称全局唯一**，不按浏览器、标签页或会话区分。重复读取更新同一记录，余额采用最新完整有效读数，原始资金基准保留最早观察值；类别变化也更新同一账户。旧重复记录归档保留，历史、每日开仓额度及锁定归到保留的账户 ID；不会因换浏览器而重置额度。同一账户仅允许一个执行窗口拥有执行权，另一个窗口可只读查看；切换执行前须先在原窗口撤销执行并确认未完成操作。网页列表中真正同名且无法唯一定位时，列表仍合并展示一行，执行会停止等待核对。

每个已识别账户的每个阶段在本工具内每交易日最多开仓一次，手动与自动策略共用额度，按美东 20:00 日切，与日亏损重置对齐。纸盘成交、已持有仓位、平仓历史中的开仓时间及已派发浏览器开仓都会占用额度；结果未知时保留占用，未派发即取消的任务不占用。重启策略、服务重启或解除策略锁定不能在同日重开第二单。工具外未观察到的交易不在此额度记录范围内。

阶段仅接受平台明确标记，按 `1/2 → 2/2 → live` 前进；旧页面、旧浏览器或未识别阶段不能回退当前阶段。新阶段重置资金基准、风险读数、当日开仓额度和自动策略锁定；手动排除、归档及主账户永久禁用保留。首次识别阶段时，旧的未分阶段日额度保守归入首次识别阶段，防止升级后同阶段重复下单。若旧阶段仍有持仓或未知请求，必须从当前页读到新阶段明确空仓后才完成切换；旧异常留存审计，不推算跨阶段成交或盈亏。已停止或暂停的策略不会因切换阶段自动启动。

任一交易确认结束后自动锁定该账户，退出自动策略。下一次美东 20:00 日切刷新每日额度，并自动清除所有本地策略锁，包括手动排除、交易结束、止损和达标锁定。服务关闭期间错过日切，会在重启后补解锁；不自动启动已停止的策略或重新加入当前批次。平台已通过 / 失败、账户风险锁及成交结果未知状态保持不变，不因解除策略锁而获得开仓资格。账户表显示预计自动解锁时间。

新订单清空页面旧止盈，只设置止损（默认 130，可修改），成交后仍须观察到正确方向的原生止损保护。已知账户目标达到或明确显示 Passed 时会请求保护性平仓；平台先行平仓时按实际空仓读数确认，并取消未派发的平仓任务。真实账户目标未读取时不猜测金额，依平台状态和实际平仓确认。策略仅在当前窗口顺序执行，不创建预备窗口。

「当日已实现盈亏」按本工具已记录的平仓交易逐账户汇总，不使用累计余额变化或浮盈亏替代。按用户设定以**纽约时间每天 17:00** 日切，区间从上次 17:00（含）至下次 17:00（不含）；正好在日切时平仓的交易归入新一天。自动处理夏令时，表头提示显示当前北京时间区间。本地没有记录的交易不会被补造，零笔历史显示 `+0.00`；未可靠关联的观察行显示未知。

同一交易日内，策略锁定跨服务重启和策略运行保留；下一次美东 20:00 自动解除。运行中也可锁定账户，取消其尚未派发的策略开仓；已派发动作仍需确认，已有持仓继续监控和平仓保护，本批全部确认结束后才开始下一批。解除锁定不会自动加入正在运行的批次，需在下一轮重新选择；已通过评估的账户即使策略锁自动解除，也不能在平台状态未变化时继续开仓。此锁定只限制自动策略，手动下单仍遵守插件执行权限及账户风控。

浏览器通过状态以页面明确的 Passed / 已通过标记或账户菜单类别为准。持仓在 Vest 原生止损或其他网页操作后结束时也会锁定；无法确认平仓原因时显示「交易结束锁定」，不推断为止盈或止损。

页面明确显示 Failed / 评估失败或 Closed / 已关闭时，工具会永久停用该号，把旧异常任务及尚未确认结束的本地持仓留存到审计记录，不再阻塞同批其他账号或下一批。Closed 单独保留为平台关闭状态；即使该号已从菜单消失或隐藏金额，仍可从当前账号徽标读取终止状态。其他批内持仓仍须全部结束，之后按原随机间隔继续；已暂停或停止的策略不会自动恢复。仅断连或从菜单消失不作为失败证据。

开仓后的持仓监控允许浮盈亏、费用导致的现金变化和风险指标持续波动；只等待账号身份及加载状态稳定，持仓 ID、方向和数量仍严格核对。尚未派发交易任务时，资金读数暂未稳定会自动等待读取，不会因此切回只读或撤销其他账号的执行许可；已派发交易结果不明确时仍停止自动重试。爆仓归档保持执行开关不变，同批结束后继续后续批次。工作台只有在确实存在待确认交易时显示「待人工核验」，归档后不保留空的核验阻塞。

当前页面已经选中目标账号时，策略直接读取第二行「未实现盈亏」，监控期间不再反复打开右上角账户列表；只有实际切换目标账号才打开列表。没有第二行字段的布局回退到账户统计卡；明确隐藏、加载中或互相冲突的第二行数值保持未知，不用其他账号或旧卡片数值替代。持仓状态仍由持仓表的实际记录确认。

每个非主账户的名称下方都有手动「归档」，正常账号也可使用。手动归档从默认列表及策略池隐藏该号、取消尚未派发的开仓，保留余额、平台状态、审计及交易历史，不会将正常账号改成评估失败，也不会暂停其他账号的策略或关闭执行开关。存在持仓或未确认交易时，须先完成处理。归档状态跨日、重启和重复读取保留，勾选「显示已归档」可查看。

「自动归档失败账户」默认开启，只处理已确认失败或关闭的账号。已消失且状态不明、仍有旧异常请求的账号，可在停止策略并明确确认评估失败后使用「确认失败并归档」；该操作与普通手动归档分开，不补造成交或盈亏。



浏览器手动下单输入 **Micro 微型合约数**，1 Micro 对应 2 Vest NQ 单位；模拟交易、服务记账、持仓及历史仍使用 **Vest 单位**。NQ 的 1 Vest 单位每点盈亏为 1 USDC；1 CME NQ 等价 20 Vest 单位。TP / SL 是每个账户单笔持仓的 USDC 金额，不是整批金额。平台规则、实际成交和通过状态以 Vest 为准。

策略参数中的「仓位大小」对应 Vest 主下单表单的 25%、50%、75%、100% 按钮，默认 25%。执行窗口点击所选按钮并核验比例滑块，等待页面计算出的 Micro 整数数量稳定；转换为 Vest 单位后在下单前固定并上报本地服务，成交后仍按该实际数量核对。比例控件缺失、数量无效或变化、权限撤销时不提交订单，不自行按余额推算浏览器账户的下单数量。

模拟账户没有 Vest 页面，仅按 `账户净值 × 仓位比例 ÷ 模拟价格` 进行 1 倍无杠杆换算，界面有明确说明；不代表平台购买力、杠杆或最大可下单数量。

## 连接真实网页

Vest Capital 当前没有官方交易 API；本项目采用浏览器界面桥接，不调用猜测的私有接口，也不读取网站密码、会话 Token 或钱包私钥。

### 读取账户并切换模式

1. 在 `edge://extensions` 或 `chrome://extensions` 加载 `extension/` 或已解压的 `vest-browser-bridge/`，已安装时重新加载至 **0.3.28**。
2. 登录 **https://next.vestmarkets.com/trade/NQ-PERP**，在工作台「浏览器连接」复制本地配对码并粘贴到插件。
3. 点击 **读取 / 刷新账户**。插件逐个读取账户名称、类别、净值与浮盈亏，完成后恢复原选账户；真实账户会自动出现在工作台同一张账户表中。
4. 在插件切换 **只读 / 执行**。只读模式只同步信息；开启时确认连接及账户身份；空闲不切换账户或准备表单。有下单任务时才准备市价、Micro 微型数量单位及 USD 止损；持仓监控和平仓不要求开仓表单。报错会保留在插件中，重新打开仍可查看。

整个流程不需要手工新增真实账户、选择绑定对象、采集身份或勾选核对清单。本地配对码只用于连接本机服务。账户与控件的准确性由程序在执行前自动校验，平台页面无法明确识别时会显示原因并切回只读。

执行模式会依次切换到任务对应账户，读到新鲜快照后才领取一次交易任务；一个页面同一时刻最多执行一个未确认动作。切回只读立即禁止后续输入和点击、取消未派发的开仓及平仓、暂停相关策略；已经发出的动作保留回执核对，不能当作已撤单。只读时原生 TP/SL 仍留在 Vest，但本地工具不再点击平仓。

每次开仓成交后，插件用实际成交均价和 NQ 数量计算止损触发价，再取最接近的 0.25 价位。正好处于两档中间时，取靠近成交均价的一档。比如 6 NQ 空单成交于 28000，配置止损 130 USDC 时，止损挂在 28021.75，对应风险 130.50 USDC。持仓列表已有该价位时直接通过核验，否则修改一次并重新读取确认。不设止损的条件仍按本单决策执行。校正无法确认时保留已成交仓位、暂停并提示核对。

执行权限存于浏览器会话，普通后台休眠不会丢失；重载扩展、浏览器重启、刷新页面、服务重启、失去连接或结果未知后默认只读，不会自动恢复执行。正常执行期间通过独立心跳维持会话，迟到的旧权限响应不能覆盖更新后的只读选择。

现金余额按 `净值 - 未实现盈亏` 计算。初始资金只记录首次观察到的现金基准，并非平台原始本金；没有读取到的平台利润目标、最大亏损均留空，不自行猜测。新订单只附每账户单笔止损，不设固定止盈；下单前自动确认 USD 及 Micro 已选中，数量换算后再与成交核对。同名账户不能可靠区分时不执行。不同浏览器个人资料的执行许可独立，但同名账户仍共用一条账户记录。

账户读取超过有效期或连接中断后，表格保留最后一次账户余额、净值、浮盈亏、账户状态及读取时间，另标记「待更新」。总览保留最后读数合计并标明待更新数量；尚未读取的金额仍显示未知。重启后也保留快照并等待更新。只读模式持续刷新当前账户；刷新所有账户时点插件读取按钮。缓存仅供查看，交易派发、仓位确认和风控操作仍要求原有新鲜读数，不因保留显示而延长执行许可。

如果出现 `Could not establish connection. Receiving end does not exist.`，请在扩展管理页重新加载 **0.3.20**，回到 Vest 页面点击「检测页面连接」。扩展先握手，缺少页面脚本时按需补加载；正常连接不会重复注入。若浏览器拒绝访问，请允许该扩展访问 `https://next.vestmarkets.com/*`。失败会退出等待并说明原因，不静默重放业务。读取进度保存在扩展中，关闭弹窗后扫描仍可继续。

0.3.15 修复带阶段账户开仓前被误报「账户身份发生变化」的问题：执行校验和自动识别统一使用包含阶段的账户指纹。真实账户或阶段变化仍会停止旧任务；已通过账户的保护性平仓继续核验同一账户。

0.3.16 支持执行模式下的第一阶段通过弹窗（中英文）：识别第一阶段完成及下一阶段 `2/2`，准备中持续等待；按钮就绪后只点击一次「开始下一阶段」。可读取的旧阶段空仓结果先同步到旧账本，切换后必须核验同名账户、新鲜 `2/2` 空仓快照及服务确认，才恢复后续调度。账户 ID 保持不变，两阶段的资金、盈亏及每日额度仍独立。只读模式不点击；其他风险、成本、实盘激活弹窗仍交由用户处理。切换未确认时停止且不重复点击，暂停或已结束策略不会自动重启。

0.3.20 支持亏损上限导致账号关闭后的详情弹窗：同时核验当前非主账户的 Closed / 已关闭徽标、已触及上限并已关闭的明确文案，以及唯一的关闭按钮。先由服务确认该号永久停用和异常归档，再只点击一次 Close；已归档账号仍留着提示时也能处理。关闭提示后继续原有批次切号，不撤销整窗执行许可；持仓面板消失、金额隐藏不阻碍明确的封号状态归档。只读或撤权期间不点击，未知或叠加弹窗仍停止，付费重购、购买账户及交易确认按钮不自动操作。已暂停或停止的策略仍需明确重新启动。

同版会在领取交易任务前展开过小的持仓面板，避免 Vest 虚拟表格尚未渲染持仓行时已提交订单；等待成交期间亦保持可读取。无法展开时先等待读取，不领取订单。失败回执缺少当前阶段时，后台保留原始读取错误并继续按“结果未知”冻结，不将其误报为阶段变化；成功回执仍严格验证阶段。接管已有未知结果持仓需要明确人工核对、同窗口只读新鲜快照及原请求的品种、阶段、方向、数量和原生保护匹配，不重放订单或补造成交。接管保持策略暂停，明确继续原轮次后才恢复原批次和参数。

上述恢复使用 [Chrome 官方 scripting API](https://developer.chrome.com/docs/extensions/reference/api/scripting)，仅注入本扩展文件到 Vest 页面主框架的隔离环境；不读取登录凭据、不重放下单或平仓任务。

扩展只处理 NQ-PERP、Micro 微型数量、市价开仓及全量市价平仓。每个账户一次最多管理一个持仓。遇到多个持仓、账户指纹变化、额外风险 / 成本 / 滑点确认框、原生保护缺失、页面变化或成交结果未知，会暂停，不自动重复下单或代为接受警告。刷新网页、重开标签页后重新连接。页面关闭、断网或电脑休眠期间，本地桥接不能执行交易；原生 TP/SL 是否有效需在 Vest 核对。

浏览器 K 线从连接后本机采集的页面中间价聚合，最多保留 720 根一分钟数据；不提供接入前官方历史，断线期间不补数据，成交量未知。实盘历史只覆盖本工具观察确认的交易；退出价格为确认时观察价，盈亏为开平仓现金余额差，可能包含费用、资金费或期间资金变动，不是精确的交易所成交回报。

结果未知的账户需要先在 Vest 人工检查并处理实际仓位和挂单，再使用「人工核对后解除锁定」。工具要求新鲜且明确空仓的页面读数；核对不会补造交易历史，也不会自动恢复原策略。

## 数据与结构

```text
src/                    React 交易工作台
server/app.py           本机 HTTP API 与静态文件服务
server/engine.py        SQLite 状态、模拟引擎、批次与桥接队列
server/strategies.py    自动策略与回测共享的策略目录及选择逻辑
server/market_history.py 8090 只读行情客户端与独立历史缓存
server/backtesting.py   确定性 Vest 规则与账户回测
server/backtest_service.py 后台历史读取及模拟任务
extension/              Manifest V3 浏览器扩展
tests/                  引擎、HTTP 与扩展验证
docs/vest-integration.md 官方文档与公开网页控件核实记录
docs/backend.md         API、执行与数据口径
docs/backtesting.md     回测使用、成本假设及统计定义
runtime/                本地数据库、配对码和运行状态（不提交 Git）
```

交易服务仅监听 `127.0.0.1`，不应暴露到公网。交易运行数据持久化在 `runtime/vest.sqlite`，其中包含本地配对码；回测行情、参数与结果保存在 `runtime/backtests.sqlite`。`runtime/`、依赖、构建文件及环境变量文件已在 `.gitignore` 排除。服务重启会暂停策略，保留已有持仓和未确认操作；不会自动继续开仓。
